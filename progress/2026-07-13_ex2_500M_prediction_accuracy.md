# ワークロード予測精度が総実行時間に与える影響（ex2, 500M スケール）

作成日: 2026-07-13

## 概要

500M スケールのワークロード（`ex2_500M`, `2h_x2_50x`）に対し、**ワークロード予測精度**を
変化させたときの**総実行時間（クエリワークロード実行時間 + マイグレーション時間の合計）**を
3 手法で比較した。

- **予測精度 (Prediction Accuracy) = 100 − ノイズ率**。
  ノイズ率 0%〜50%（5%刻み）の実験結果を、精度 100%〜50% に対応させている。
- 総実行時間は各ベンチマーク結果の `total_benchmark_time` を使用。

| 手法 | 説明 | 結果ファイル |
|---|---|---|
| **Adapt** | 過去のワークロードのみを参照する適応手法 | `benchmark_results_adaptive_w4_2h_x2_50x.json` |
| **Static** | 静的最適化 | `benchmark_results_static_2h_x2_50x_noise*.json` |
| **Proposed** | 提案手法（時間依存 dynamic） | `benchmark_results_dynamic_2h_x2_50x_noise*.json` |

**Adapt は過去のワークロードしか参照しない**ため、将来ワークロードの予測精度（ノイズ率）に
依存しない。したがって全精度でノイズ 0% 時の値のままとなり、グラフ上は**横一直線**で表される。

## 考察

- **予測精度が高いほど Proposed・Static ともに総実行時間が減少**し、ほぼ線形に改善する。
  Proposed は全精度域で Static を下回り、精度が上がるほど両者の差は拡大する。
- **Proposed は精度 55% 以上で全手法中最速。** 予測がある程度当たれば（誤差 45% 以下）、
  将来ワークロードを見越した MV 配置が効き、Adapt・Static を明確に上回る。
- **交点（Adapt との比較）。** Adapt は精度非依存で一定（414,284 秒）。
  - Proposed は精度 50%〜55% の間で Adapt を下回る。
  - Static は精度 60% 付近で Adapt と同等（60% で 413,233 ≒ 414,284）、それ以上で下回る。
  - つまり予測精度が極端に低い（≈50%）領域でのみ、過去参照の Adapt が相対的に有利になる。
- **高精度域での優位性は大きい。** 精度 100% では Proposed 52,098 秒に対し、
  Static は約 2.7 倍（141,992 秒）、Adapt は約 8.0 倍（414,284 秒）を要する。

## まとめ

提案手法（Proposed）は、ワークロード予測精度が現実的な水準（おおむね 55% 以上）にある限り、
Static・Adapt を一貫して上回る総実行時間を達成する。予測精度が高いほどその優位性は拡大し、
将来ワークロードを見越した時間依存 MV 最適化の有効性が確認できた。予測精度が極端に低い
（≈50%）場合にのみ、過去のワークロードのみを参照する Adapt が相対的に有利となる。

## 備考

- 縦軸「総実行時間」= `total_benchmark_time`（クエリワークロード実行時間 + マイグレーション時間）。
  Static はマイグレーションの代わりに初期 MV 構築時間 `initial_mv_creation_time` を含むが、
  いずれも `total_benchmark_time` に含まれるため 3 手法とも同一指標で比較している。
- 横軸「予測精度」= 100 − ノイズ率。ノイズ率 0%〜50%（5%刻み）に対応。
- Adapt はノイズ 0% の 1 点のみを実測し、過去参照特性から全精度に同値を適用（横一直線）。
